# Convergence Example Workflow

## Overview

This workflow demonstrates **iterative refinement with convergence testing** using the hybrid loop system. It simulates a convergence algorithm that refines a value until the change (delta) falls below a specified threshold.

## Purpose

- **Primary**: Demonstrate loop execution with phase-based convergence control
- **Secondary**: Showcase hybrid loop architecture (declarative + dynamic control)
- **Educational**: Provide a complete working example of convergence testing pattern

## Workflow Structure

```
Phase 1: Setup and Initialization
  ↓
┌─→ Phase 2: Process Iteration        ←┐
│   ↓                                  │
│   Phase 3: Analyze Results           │
│   ↓                                  │
└── Phase 4: Validate and Check        │
    Convergence                        │
    (decides: continue or exit)  ──────┘
```

## Loop Configuration

This workflow demonstrates **hybrid loop control** combining declarative and imperative approaches:

```yaml
loops:
  - name: refinement-loop
    description: "Iterative refinement until convergence"
    phases: [2, 3, 4]
    max_iterations: 15
    # Declarative exit condition
    exit_condition:
      expression: "$CONVERGENCE_DELTA < $CONVERGENCE_THRESHOLD"
      description: "Exit when convergence achieved"
    # Allow phase override for exceptional cases
    allow_phase_control: true
```

**Hybrid Approach Benefits**:
- `exit_condition`: Provides clear, validated convergence criteria (visible in workflow.yaml)
- `allow_phase_control`: Allows Phase 4 to override for errors or early exit
- **Best of both worlds**: Declarative default + imperative flexibility

## Parameters

### Required
- `OUTPUT_DIR` (directory): Output directory for iteration results

### Optional
- `CONVERGENCE_THRESHOLD` (number): Delta threshold for convergence (default: 0.01)
- `MAX_LOOP_ITERATIONS` (integer): Maximum iterations allowed (default: 15)
- `INITIAL_VALUE` (number): Starting value for convergence (default: 1.0)

## How It Works

### Convergence Algorithm

Each iteration applies a refinement formula:
```
new_value = current_value × 0.7
```

This causes the value to converge toward 0 over multiple iterations.

### Convergence Check

After each iteration, Phase 4 calculates:
```
delta = |new_value - current_value|
```

**If delta < threshold**: Loop exits (converged)
**If delta ≥ threshold**: Loop continues (not converged)

### Loop Control Priority

The system evaluates loop continuation in this order:

1. **max_iterations (15)**: Safety limit - workflow aborts if exceeded (highest priority)
2. **LOOP_CONTINUE parameter**: Phase 4 can override for exceptional cases (errors, early exit)
3. **exit_condition**: Orchestrator evaluates `$CONVERGENCE_DELTA < $CONVERGENCE_THRESHOLD`
4. **Default**: Would exit if no control mechanism active

**Normal execution**: exit_condition handles convergence check (step 3)
**Exceptional cases**: Phase 4 uses LOOP_CONTINUE override (step 2)

## Key Features Demonstrated

### 1. Hybrid Loop Control
- **Declarative exit_condition**: `$CONVERGENCE_DELTA < $CONVERGENCE_THRESHOLD` in workflow.yaml
- **Phase override**: Phase 4 can override with LOOP_CONTINUE for exceptional cases
- **Best practice**: Use exit_condition for standard convergence, override for errors

### 2. Automatic Loop Parameters
- `LOOP_INDEX`: Current iteration (1, 2, 3, ...)
- `LOOP_NAME`: "refinement-loop"
- `LOOP_ITERATION`: Alias for LOOP_INDEX

### 3. State Management
- Parameters accumulate across iterations
- `CURRENT_VALUE` updates each iteration
- `ITERATION_COUNT` tracks total

### 4. Safety Mechanisms
- `max_iterations`: Prevents infinite loops
- Validation at each iteration
- Clear exit conditions

### 5. Traceability
- `loop_state.yaml`: Iteration history
- Validation reports: Decision rationale
- Iteration files: Full state per iteration

## Extending This Example

### Different Convergence Algorithms

Replace the formula in phase-02-process.md:
```bash
# Newton-Raphson method
PROCESSED_VALUE=$(echo "$CURRENT_VALUE - (f($CURRENT_VALUE) / df($CURRENT_VALUE))" | bc -l)

# Gradient descent
PROCESSED_VALUE=$(echo "$CURRENT_VALUE - $LEARNING_RATE * gradient($CURRENT_VALUE)" | bc -l)

# Binary search
PROCESSED_VALUE=$(echo "($CURRENT_VALUE + $TARGET) / 2" | bc -l)
```

### Multiple Convergence Criteria

In phase-04-validate.md, combine conditions:
```bash
DELTA_CONVERGED=$(echo "$CONVERGENCE_DELTA < $CONVERGENCE_THRESHOLD" | bc -l)
QUALITY_MET=$(echo "$QUALITY_SCORE >= 0.95" | bc -l)

if [ "$DELTA_CONVERGED" -eq 1 ] && [ "$QUALITY_MET" -eq 1 ]; then
  LOOP_CONTINUE="false"
  LOOP_REASON="Both delta and quality criteria met"
else
  LOOP_CONTINUE="true"
  LOOP_REASON="Criteria not met: delta=$DELTA_CONVERGED, quality=$QUALITY_MET"
fi
```

## Troubleshooting

### Loop Never Exits
- Check CONVERGENCE_THRESHOLD is achievable
- Verify convergence algorithm is correct
- Check max_iterations setting
- Review loop_state.yaml for iteration history

### Exceeds Max Iterations
- Increase MAX_LOOP_ITERATIONS parameter
- Relax CONVERGENCE_THRESHOLD
- Adjust convergence algorithm parameters

### No LOOP_INDEX
- Ensure orchestrator injected parameters correctly
- Check phase is within loop.phases range
- Verify workflow.yaml loop configuration
