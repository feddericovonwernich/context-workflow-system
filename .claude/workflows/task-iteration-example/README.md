# Task Iteration Example Workflow

## Overview

This workflow demonstrates the **task iteration** feature, which allows executing a single phase multiple times (once per task) to prevent context exhaustion when processing large lists of independent work items.

## Purpose

Task iteration is designed for scenarios where:
- You have many independent tasks to process (e.g., 50 API endpoints to document)
- Each task requires similar processing but with different inputs
- Running all tasks in a single agent would exhaust context
- Tasks may have dependencies on each other
- Resumption support is needed (restart from failures)

## Workflow Phases

### Phase 1: Setup and Task Generation
- Creates output directory structure
- Generates example task definition files
- Creates task index with execution order
- Demonstrates batch organization and dependency declaration

**Outputs**:
- `task-index.json` - Master index with batches and execution order
- `tasks/TASK-*.json` - Individual task definitions

### Phase 2: Process Single Task (Task Iteration Phase)
- **Executed multiple times** via task iteration (once per task)
- Each invocation processes exactly one task in isolation
- Fresh agent context per task (prevents context exhaustion)
- Checks dependencies before processing
- Generates individual result files

**Key Feature**: This phase runs with `task_iteration.enabled = true`, so the orchestrator automatically:
- Loads the task index
- Launches one agent per task sequentially
- Passes `TASK_ID` parameter to each invocation
- Aggregates all results
- Supports resumption (skips completed tasks)

**Outputs**:
- `task-results/TASK-*-result.json` - One result file per task
- `task-results.json` - Aggregated results (generated by orchestrator)

### Phase 3: Aggregate Results
- Loads aggregated task results
- Generates summary statistics
- Creates human-readable report
- Displays final metrics

**Outputs**:
- `summary-report.md` - Comprehensive summary of all task results

## Task Iteration Configuration

```yaml
task_iteration:
  enabled: true                   # Enable task iteration
  phase: 2                        # Phase 2 will iterate over tasks
  task_index_param: TASK_INDEX_PATH  # Parameter with task index path
  task_id_param: TASK_ID          # Parameter to pass current task ID
  task_dir: "tasks"               # Directory with task definitions
  result_dir: "task-results"      # Directory for result files
  max_retries_per_task: 1         # Retry failed tasks once
  stop_on_failure: false          # Continue despite failures
  sequential: true                # Execute one task at a time
```

```json
  "task_id": "TASK-3",
```

```json
  "outputs": {
    "processed_data": "ITEM-3",
    "timestamp": "2025-12-18T12:05:30Z"
  },

}
```


## Key Features Demonstrated

### 1. Context Efficiency
Each task executes in a fresh agent with minimal context:
- Phase 2 prompt: ~100 lines
- No accumulated context from previous tasks
- Guaranteed completion of all tasks regardless of count

### 2. Dependency Tracking
- TASK-3 depends on TASK-1
- TASK-5 depends on TASK-2
- Orchestrator ensures dependencies complete first
- Tasks execute in correct order via batches

### 3. Resumption Support
If workflow is interrupted:
```bash
/run-workflow .claude/workflows/task-iteration-example
```
- Automatically skips completed tasks
- Resumes from first incomplete/failed task
- No duplicate processing

### 4. Result Aggregation
- Individual result files: `task-results/TASK-*-result.json`
- Aggregated file: `task-results.json` (orchestrator-generated)
- Runtime parameters updated: `TASKS_COMPLETED`, `TASKS_FAILED`, `TASKS_BLOCKED`

### 5. Batch Execution
- Tasks organized in batches
- Batch 1: Independent tasks (no dependencies)
- Batch 2: Dependent tasks (after dependencies satisfied)
- Clear progress tracking per batch

## Integration with Other Features

### Model Selection
Works seamlessly with per-phase model selection:
```yaml
phase_metadata:
  model: opus  # All task iterations use opus
```

### Parallel Execution
Task iteration is **mutually exclusive** with parallel execution:
- Task iteration: One agent per task, sequential
- Parallel execution: Multiple agents per work item, concurrent
- Use task iteration when: many tasks, need resumption, have dependencies
- Use parallel execution when: fewer work items, no dependencies, speed critical

## Troubleshooting

**Issue**: "task-index.json not found"
- **Cause**: Phase 1 didn't complete or failed
- **Solution**: Check phase 1 output, verify OUTPUT_DIR is writable

**Issue**: "Task X blocked (dependencies not satisfied)"
- **Cause**: Dependency task failed or didn't complete
- **Solution**: Check result files for dependency tasks, retry if needed

**Issue**: "No result file generated"
- **Cause**: Phase 2 agent crashed or didn't create result file
- **Solution**: Check execution logs, ensure phase 2 always creates result file

## Comparison with Standard Execution

| Feature | Standard Execution | Task Iteration |
|---------|-------------------|----------------|
| Context per execution | Cumulative (all tasks) | Isolated (one task) |
| Resumption support | No | Yes (skip completed) |
| Dependency tracking | Manual | Automatic |
| Scalability | Limited by context | Unlimited tasks |
| Progress tracking | Implicit | Explicit (per task) |
| Retry logic | Phase-level | Task-level |
